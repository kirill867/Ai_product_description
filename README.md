
# AI Product Description Generator

Локальный сервис для генерации SEO-контента карточек технических товаров с использованием Large Language Models (LLM).

Проект разработан в рамках тестового задания на позицию AI / LLM Developer.

## Возможности

- Генерация SEO Title и SEO Description.
- Создание поисковых запросов для карточки товара.
- Формирование коммерческого блока на основе исходных данных.
- Автоматическое определение отсутствующих характеристик.
- Проверка длины SEO-полей.
- Эвристическое обнаружение неподтверждённых утверждений и числовых значений.
- Повторная генерация при обнаружении исправимых проблем.
- Пакетная обработка товаров через API.
- Валидация входных данных с помощью Pydantic.

## Архитектура решения

Процесс генерации состоит из следующих этапов:

1. API принимает структурированные данные о товаре.
2. Pydantic проверяет входные данные.
3. Приложение формирует prompt с ограничениями на использование фактов.
4. LLM генерирует SEO Title, SEO Description и поисковые запросы.
5. Приложение извлекает JSON из ответа модели.
6. Python формирует коммерческий блок на основе входных данных.
7. Python определяет отсутствующие характеристики.
8. Выполняются проверки качества сгенерированного контента.
9. При обнаружении исправимых проблем возможна одна повторная генерация.
10. API возвращает результат в JSON.

### Разделение ответственности

| Компонент | Ответственность |
|---|---|
| FastAPI | HTTP API и обработка запросов |
| Pydantic | Валидация входных и выходных данных |
| LLM | Генерация SEO-контента |
| Python | Коммерческий блок и missing fields |
| Quality validation | Проверка структуры и потенциальных проблем контента |

Такое разделение позволяет не передавать модели контроль над бизнес-правилами и формированием обязательных полей.

## Установка

Клонировать репозиторий:

```bash
git clone https://github.com/kirill867/Ai_product_description.git
cd ai_product_description
```

Создать виртуальное окружение:

```bash
python -m venv app/.venv
```

Активировать виртуальное окружение в Windows Git Bash:

```bash
source app/.venv/Scripts/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

## Настройка

Создать файл `.env` на основе `.env.example`.

Пример конфигурации:

```env
LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=qwen2.5:3b

LLM_TIMEOUT=300
LLM_MAX_TOKENS=2200
```

Для локального запуска используется Ollama.

Загрузить модель:

```bash
ollama pull qwen2.5:3b
```

Запустить Ollama:

```bash
ollama serve
```

При использовании другой OpenAI-compatible модели необходимо изменить `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`.

## Запуск приложения

Из корневой директории проекта выполнить:

### POST /generate

Генерация карточки одного товара.

Пример входных данных:

```json
{
  "name": "Манометр ДМ 02",
  "manufacturer": "Манотомь",
  "specs": {
    "Диапазон измерений": "0–1.6 МПа",
    "Класс точности": "1.5",
    "Присоединительная резьба": "G1/2",
    "Диаметр корпуса": "100 мм"
  },
  "description": "Манометр предназначен для измерения давления."
}
```

Пример структуры ответа:

```json

  },
```

### POST /generate/batch

Пакетная генерация карточек.

Принимает массив товаров в поле `products`.

Ограничения:
- Минимум: 1 товар.
- Максимум: 20 товаров за запрос.
- Товары обрабатываются последовательно для снижения нагрузки на локальную LLM.

## Контроль качества и достоверности

Для контроля результата реализованы следующие проверки:

| Проверка | Назначение |
|---|---|
| SEO Title length | Проверка ограничения до 70 символов |
| SEO Description length | Проверка целевого диапазона 800–1200 символов |
| Search queries count | Проверка наличия 3–5 запросов |
| Unsupported phrases | Поиск потенциально неподтверждённых рекламных утверждений |
| Unknown numbers | Поиск числовых значений, отсутствующих во входных данных |

Проверки являются эвристическими и не гарантируют полного отсутствия галлюцинаций.

### Работа с недостаточными входными данными

Если исходных данных недостаточно для SEO Description длиной 800–1200 символов, приложение не дополняет текст выдуманными характеристиками или повторяющимися фразами.

Фактическая точность имеет приоритет над достижением целевой длины.

В таком случае `seo_description_length_valid` будет иметь значение `false`, а `seo_description_target_not_met` — `true`.

### Недостающие характеристики

Список отсутствующих характеристик формируется программно на основе заранее определённого набора важных полей.

Это позволяет не зависеть от того, какие характеристики модель решила включить в свой ответ.

## Ограничения текущей версии

- Качество генерации зависит от выбранной LLM.
- Производительность локальной модели зависит от оборудования.
- Эвристические проверки не обеспечивают полного обнаружения галлюцинаций.
- Список важных характеристик требует адаптации под конкретные категории товаров.
- Для промышленного использования необходимы дополнительные автоматизированные тесты, расширенная проверка фактов и мониторинг качества генерации.
